# 搜索策略

当前是面向小数据量的后端词法搜索，策略名 `weighted-lexical-fuzzy-v1`；没有使用向量模型、外部搜索引擎或个性化搜索。

## 实际行为

- 输入归一化：Unicode NFKC，全角变半角，英文不区分大小写。
- 查询拆词：英文/数字串与连续汉字段；空格可明确分开多个关键词。
- 评分字段：标题权重 8、话题 6、作者名 5、正文 2。字段完全相同乘 3，字段内包含乘 2。
- 模糊匹配：长度至少 4 的词使用字符序列相似度，候选长度差不超过 1，阈值为 `1−1/词长`；长汉字片段使用同长度滑动窗口。近似命中仅给字段权重的 0.5 倍，所以正常匹配优先。
- 多词查询要求每个词都能在某个字段命中；最多处理前 12 个词，输入最长 100 字。
- 各词最高字段分相加，按总分降序；同分保留新内容优先。搜索结果不会再进行作者打散，避免破坏相关性。
- 返回 `search_score`、`search_matches`，界面显示命中字段，近似匹配明确标注。
- 屏蔽过滤与关注流过滤仍在评分前应用。前端输入防抖 300ms，调用后端；不再依赖前端 includes 筛选。

例：`ＰＹＴＨＯＮ` 可匹配 `Python`，`pythn` 可近似匹配 `Python`；`python cooking` 必须两个词都有命中。标题提到 Python 通常排在仅正文提到 Python 的结果之前。

## 局限

不具备中文语义分词、拼音/同音纠错、同义词扩展、语义理解、拼写建议或搜索词高亮。两个字的中文错别字不做宽松匹配，以避免大量误命中。`AI` 不会自动等同于 `人工智能`。

当前仍逐条扫描内容，没有倒排索引；数据规模上来后成本会增长，不是生产搜索架构。后续可选择中文分词与索引、业务词典、拼音召回，再评估是否需要向量混合检索；需要用真实查询和人工标注结果验证相关性，而不是只调整权重。
